# Market Watch New Listings

Market Watch has Market and New Listings modes, matching the Magic Swap mode buttons. Market retains prices and charts. New Listings displays exchange listing announcements, searchable by ticker, exchange, or title, newest first. It is not a feed of all newly minted tokens.

The switcher uses the provider's official 192px PNG favicon, downloaded from https://newlistings.pro/favicon-nlf.png into `public/new-listings-favicon.png`, displayed at 18px and served locally.

Listing cards display circular token logos from the provider's public feed. `new-listings-icons.js` refreshes that page at most once a minute with one shared request, a four-second timeout and a 2 MiB response limit. Artwork is matched by exact provider event ID and the complete ordered symbol list, never by ticker alone. Only the provider's token-image URLs are accepted. Up to 200 matched events are cached in Render memory; the source page only exposes its recent cards, so older or newly detected events may have no matched artwork. Those cards, and failed images, display ticker initials. Source-page outages preserve the durable announcements. The browser loads the same source images with no referrer. No extra WebSocket, key, Worker change, or wallet change is needed. Deploy `new-listings-icons.js`, `backend-server.js` and `public/index.html` together to release the logos.

Each listing now has a compact interactive line chart using the existing Chart.js renderer. It loads as the card approaches the viewport, supports 1H/6H/1D/7D ranges, expansion, hover/tap prices, and token selection for multi-token notices. The yellow marker is the listing detection time, not a claim that trading started then. Prices are actual candle closes in the market's native quote currency; KRW and USDT are not relabeled USD. Empty intervals remain chart gaps, and the latest candle may still be forming. Available coverage and retrieval time are displayed. These are cached snapshots, refreshed by range changes or reopening the view, not streaming ticks.

`GET /api/market/new-listings/:id/chart?symbol=PONS&range=6h` accepts only a token belonging to a retained listing. `new-listings-charts.js` checks the announcing exchange's official catalog for an exact base/quote pair, honoring declared quote markets. Public spot candle adapters cover Coinbase, Upbit, Bithumb, MEXC and Binance; no API key or new dependency is needed. Existing global-market symbol searches and aggregate price fallbacks are not used for listing charts. Catalogs are cached for five minutes, chart results for one minute, with shared in-flight requests and bounded cache/response sizes. Exchange requests time out after six seconds; failures and absent markets remain unavailable rather than generating history.

When an exact-exchange chart is absent, `new-listings-chart-reference.js` can read the exact provider listing's public metadata and use its explicit Coinbase spot-market link. This requires matching provider event ID, announcing exchange, original announcement URL and asset ticker, then verifying the linked pair against Coinbase's catalog. It does not search other exchanges by ticker. Reference charts prominently name the actual price venue and show “Reference for [announcing exchange]”; the source listing link remains visible. This follows the provider's token identification, not an independently confirmed on-chain contract match. Missing or changed public metadata, absent Coinbase links, unsupported markets and empty history fail closed. The provider blocks iframes, so no source page is embedded and no private chart API is called.

Local live check on October 8: Coinbase PONS-USD returned 67 real 5-minute candles, also usable as the source-linked reference for the current Bithumb/Upbit PONS notices; MEXC DARKUSDT returned 12 candles. WHUF/IBVM had no recent candle history from the probed announcing exchange. Other unsupported/unmatched notices remain explicit unavailable states. Evidence: `.local-artifacts/new-listings-charts-live.json`. Deploy `new-listings-charts.js`, `new-listings-chart-reference.js`, `backend-server.js` and `public/index.html` together; the collector Worker and wallet are unchanged. Local verification does not establish deployed Render reachability.

Official candle references: [Coinbase](https://docs.cdp.coinbase.com/api-reference/exchange-api/rest-api/products/get-product-candles), [Upbit](https://docs.upbit.com/kr/reference/list-candles-minutes), [Bithumb](https://apidocs.bithumb.com/reference/%EB%B6%84minute-%EC%BA%94%EB%93%A4-%EC%A1%B0%ED%9A%8C), [MEXC](https://mexcdevelop.github.io/apidocs/spot_v3_en/), [Binance](https://developers.binance.com/docs/binance-spot-api-docs/rest-api/market-data-endpoints).

The existing `chainlens-search` Cloudflare Worker owns collection through the `NEW_LISTINGS` SQLite-backed Durable Object. One object named `newlistings-full-v2` maintains one authenticated, receive-only provider WebSocket. The key is stored as Worker secret `NEW_LISTINGS_KEY`; never place it in public files. Magic Money's swap Worker is unchanged; it can consume this same shared feed in a future integration.

The browser polls `/api/market/new-listings` every five seconds only while New Listings is open. The updated Render backend proxies the Cloudflare snapshot through `new-listings-proxy.js`, with an eight-second timeout, and no longer opens a provider socket. Override the default Worker base with server variable `NEW_LISTINGS_WORKER_BASE_URL` if required. Worker outages return HTTP 503; the UI retains previously loaded events and reports unavailable. Responses contain sanitized recent announcements and connection status, never credentials or account identity.

The newest 200 events and diagnostics are saved immediately into durable SQLite storage, deduplicated by provider ID or source URL plus timestamp. They survive Render sleep/restarts and Durable Object restarts. A persisted 30-second alarm maintains collection without visitors; a one-minute cron recovers the connection/alarm if inactive. Outbound sockets do not hibernate and their own eviction protection lasts only 15 minutes, so the collector relies on explicit watchdog activity. Cloudflare runtime restarts reconnect from storage. The free provider plan has no historical backfill or WebSocket replay, so reconnects can still leave gaps. The provider delay comes from READY; it does not include polling or transit time.

READY confirms admission; socket open alone does not. The handshake deadline is cleared after the upgrade so it cannot abort an admitted connection later. Transient failures retry with exponential backoff and jitter, respecting Retry-After. Connection-limit failures wait at least 60 seconds. Auth, expiry and invalid-message errors stop retries; a corrected Worker key resets fatal state using a stored SHA-256 fingerprint. Raw keys are never stored in SQLite or returned. Protocol pings/pongs are handled by Cloudflare, without invented application heartbeat messages. HTTPS source links only, React text rendering, bounded fields and payloads.

The snapshot preserves `state`, `delayMs`, `updatedAt`, `events`, and sanitized `diagnostics`, adding `storage: "cloudflare-sqlite"` and `historyAvailable: false`. Diagnostics include collector start and latest READY time, last received message/event times, lifetime received/accepted/ignored/duplicate counters, connection count, restart count, watchdog time and sanitized error/close codes. No raw payloads, keys, usernames or upstream error messages are exposed. Compare provider timestamps with the connection time before attributing an empty feed to filtering. `ignoredEvents` includes non-listing announcements and invalid listing records; it alone does not identify a parser bug.

Shared read endpoint: `https://chainlens-search.guildfordking.workers.dev/api/market/new-listings`. GET is public to server/app clients; browser CORS allows configured ChainLens origins. Other browser origins and mutation methods are rejected. Future Magic Money integration can consume this endpoint through its server or add its verified app origins. It must not create another provider connection. Keep production to one collector; provider IP and connection limits still apply. Existing Worker search routes/settings are retained.

Deploy from `cloudflare-search-worker`: run `npm run check`, `npm test`, `npm run deploy:dry-run`, configure `NEW_LISTINGS_KEY` through protected stdin to `wrangler secret bulk` or `wrangler secret put`, then `npm run deploy`. Verify live READY admission and advancing `diagnostics.lastWatchdogAt` after no HTTP requests. Deploy `backend-server.js`, `new-listings-proxy.js` and the New Listings copy in `public/index.html` to Render, then verify ChainLens's public endpoint reports `storage: "cloudflare-sqlite"`. The Render key is no longer needed once that backend update is deployed.

One continuously active object uses approximately 11,059 GB-s/day at Cloudflare's published 128 MB duration rate, below the 13,000 GB-s/day free allowance by itself. Other Durable Objects on the account share that allowance; request and storage limits also apply. No account upgrade is required by this design; monitor actual usage.
